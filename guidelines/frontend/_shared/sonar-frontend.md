## 🛡️ Métricas Obrigatórias do Quality Gate no Frontend (Jest)

- **`QG:Coverage` — Cobertura de Testes Unitários em Jest >= 75.0%** (`BLOCKER`): Todo código JS/TS deve atingir `>= 75.0%` de cobertura combinada (linhas + branches via `jest --coverage` / LCOV). Cubra fluxos principais, `if/else`, ternários, `switch` e `catch`. | ❌ `test('ok', () => expect(fn(1, true)).toBe(2)); /* ramo false sem cobertura (<75%) */` → ✅ `test.each([[1,true,2],[1,false,1]])('fn(%i,%s)', (a,b,e) => expect(fn(a,b)).toBe(e));`
- **`QG:SkippedUnitTests` — Zero Testes Pulados no Jest (`Skipped = 0`)** (`BLOCKER`): Proibido commitar testes com `test.skip()`, `it.skip()`, `describe.skip()`, `xit()` ou `xdescribe()`. | ❌ `it.skip('valida form', () => expect(validar()).toBe(true));` → ✅ `it('valida form', () => expect(validar()).toBe(true));`
- **`QG:UnitTestErrorsAndFailures` — Zero Erros e Zero Falhas no Jest (`Errors = 0`, `Failures = 0`)** (`BLOCKER`): Toda a suíte Jest deve passar com `0` erros e `0` falhas. | ❌ `test('api', async () => { await apiSemMock(); });` → ✅ `test('api', async () => { jest.spyOn(api,'get').mockResolvedValue(ok); await expect(api.get()).resolves.toBe(ok); });`
- **`QG:DuplicatedLines` — Densidade de Linhas Duplicadas <= 3.0%** (`BLOCKER`): Não repita blocos TS/JS, HTML ou CSS (`<= 3.0%`). Extraia componentes, hooks, funções utilitárias ou classes CSS. | ❌ `Duplicar funções/componentes mudando apenas uma constante` → ✅ `Extrair componente/hook/função parametrizada`
- **`QG:RatingsA` — Ratings A em Reliability, Security e Maintainability** (`BLOCKER`): Exige `0` Bugs (inclusive `MINOR`), `0` Vulnerabilities (inclusive `MINOR`) e Dívida Técnica `<= 5.0%`. | ❌ `if (x === NaN) {} /* Bug: rebaixa Reliability Rating */` → ✅ `if (Number.isNaN(x)) {}`

## 🔴 BLOCKER (Falha em `Blocker Issues > 0`) (27 regras)

- **`js/ts:S1219` — Instruções 'switch' não devem conter rótulos diferentes de 'case'** (`BLOCKER`): Inserir rótulos de salto ('label:') dentro de blocos 'switch' é altamente confuso e frequentemente decorre de um erro de digitação em 'case' ou 'default'. | ❌ `switch (day) { case 1:defaul: return 'Segunda'; }` → ✅ `switch (day) { case 1: default: return 'Segunda'; }`
- **`js/ts:S128` — Cláusulas 'case' de um 'switch' devem terminar com uma instrução 'break' incondicional** (`BLOCKER`): Deixar a execução vazar de um 'case' para o próximo (fallthrough) sem 'break', 'return' ou 'throw' quase sempre introduz bugs silenciosos. | ❌ `switch (x) { case 1: doOne(); case 2: doTwo(); break; }` → ✅ `switch (x) { case 1: doOne(); break; case 2: doTwo(); break; }`
- **`js/ts:S1314` — Literais octais legados não devem ser utilizados** (`BLOCKER`): Números iniciados com zero (como '071') são interpretados como octais em modo não-estrito, o que confunde desenvolvedores. Use o prefixo '0o' ou decimal. | ❌ `const fileMode = 0755;` → ✅ `const fileMode = 0o755;`
- **`js:S1526` — Variáveis declaradas com 'let' ou 'const' não devem ser acessadas antes da declaração** (`BLOCKER`): Acessar variáveis 'let' ou 'const' na Temporal Dead Zone (antes da linha de declaração) lança um 'ReferenceError' em tempo de execução. | ❌ `console.log(count); let count = 0;` → ✅ `let count = 0; console.log(count);`
- **`js:S1527` — Palavras reservadas futuras não devem ser usadas como identificadores** (`BLOCKER`): Usar palavras reservadas da especificação ECMAScript (como 'implements', 'interface', 'package', 'private') como nomes de variáveis causa erros no modo estrito. | ❌ `const package = 'meu-pacote';` → ✅ `const packageName = 'meu-pacote';`
- **`js/ts:S2068` — Credenciais fixadas no código (hardcoded) são sensíveis à segurança** (`BLOCKER`): Senhas e segredos atribuídos a variáveis contendo termos como 'password', 'pwd' ou 'passwd' no código-fonte podem ser comprometidos. Use cofres de segredos ou variáveis de ambiente. *(Params: `passwordWords=password, pwd, passwd`)* | ❌ `const password = 'SuperSecretPassword123!';` → ✅ `const password = process.env.DB_PASSWORD;`
- **`js:S2189` — Laços de repetição não devem ser infinitos** (`BLOCKER`): Um laço cuja condição nunca se torna falsa e que não possui 'break', 'return' ou 'throw' travará a execução do programa. | ❌ `while (true) { doWork(); }` → ✅ `while (hasMoreWork()) { doWork(); }`
- **`js/ts:S2699` — Testes automatizados devem conter asserções** (`BLOCKER`): Um caso de teste que apenas executa funções sem verificar nenhum resultado com 'expect' ou 'assert' só detecta exceções não tratadas e dá falsa segurança. | ❌ `test('calcula soma', () => { sum(2, 3); });` → ✅ `test('calcula soma', () => { expect(sum(2, 3)).toBe(5); });`
- **`js:S2703` — Variáveis devem sempre ser declaradas explicitamente com 'let' ou 'const'** (`BLOCKER`): Atribuir valor a um identificador não declarado cria uma variável global implícita (ou lança erro em modo estrito), poluindo o escopo global. | ❌ `function countItems() { total = 10; return total; }` → ✅ `function countItems() { const total = 10; return total; }`
- **`js/ts:S2755` — Analisadores XML (parsers) não devem ser vulneráveis a ataques XXE** (`BLOCKER`): Habilitar a resolução de entidades externas (XXE) ao processar XML não confiável permite leitura de arquivos locais e ataques de SSRF. | ❌ `libxmljs.parseXml(xmlInput, { noent: true });` → ✅ `libxmljs.parseXml(xmlInput, { noent: false });`
- **`js/ts:S2970` — Asserções em testes Jest devem ser completas** (`BLOCKER`): Referenciar métodos de asserção do Jest (como expect(x).toBeNull ou expect(x).toBeDefined sem parênteses) sem invocá-los faz o teste passar silenciosamente sem validar nada. | ❌ `expect(result).toBeDefined;` → ✅ `expect(result).toBeDefined();`
- **`js/ts:S3516` — Funções não devem retornar sempre o mesmo valor constante** (`BLOCKER`): Se uma função possui múltiplos pontos de retorno mas todos retornam exatamente o mesmo valor, o retorno é invariante e pode indicar um erro de lógica. | ❌ `function validate(x: number) { if (x < 0) { logError(); return false; } return false; }` → ✅ `function validate(x: number) { if (x < 0) { logError(); return false; } return true; }`
- **`js:S3796` — Callbacks de métodos de array devem conter instruções 'return'** (`BLOCKER`): Métodos como 'map', 'filter', 'find', 'every', 'some' e 'reduce' dependem do valor retornado pelo callback; esquecer o 'return' preenche o resultado com 'undefined'. | ❌ `const ids = users.map(u => { u.id; });` → ✅ `const ids = users.map(u => u.id);`
- **`js:S3827` — Variáveis devem ser declaradas antes de serem utilizadas** (`BLOCKER`): Referenciar um identificador que não foi declarado em nenhum escopo acessível nem importado lança um 'ReferenceError' em tempo de execução. | ❌ `function show() { return undeclaredVar + 1; }` → ✅ `function show(declaredVar: number) { return declaredVar + 1; }`
- **`js/ts:S6265` — Conceder acesso público a objetos AWS S3 via ACLs é sensível à segurança** (`BLOCKER`): Usar ACLs como 'PUBLIC_READ' ou 'PUBLIC_READ_WRITE' em buckets S3 expõe dados sensíveis publicamente. Utilize 'PRIVATE' e políticas de acesso restritas. | ❌ `new s3.Bucket(this, 'MyBucket', { accessControl: s3.BucketAccessControl.PUBLIC_READ });` → ✅ `new s3.Bucket(this, 'MyBucket', { accessControl: s3.BucketAccessControl.PRIVATE });`

- **`js/ts:S6270` — Políticas AWS IAM que concedem acesso a qualquer principal ('*') são sensíveis à segurança** (`BLOCKER`): Usar 'new iam.AnyPrincipal()' ou 'Principal: "*"' em uma política de recurso com efeito 'ALLOW' concede acesso público irrestrito a qualquer conta AWS. | ❌ `new iam.PolicyStatement({ effect: iam.Effect.ALLOW, principals: [new iam.AnyPrincipal()], actions: ['s3:GetObject'] });` → ✅ `new iam.PolicyStatement({ effect: iam.Effect.ALLOW, principals: [new iam.AccountRootPrincipal()], actions: ['s3:GetObject'] });`
- **`js/ts:S6299` — Desabilitar a criptografia em sistemas de arquivos AWS EFS é sensível à segurança** (`BLOCKER`): Sistemas de arquivos EFS devem ter a criptografia em repouso habilitada ('encrypted: true') para proteger dados compartilhados. | ❌ `new efs.FileSystem(this, 'Fs', { vpc, encrypted: false });` → ✅ `new efs.FileSystem(this, 'Fs', { vpc, encrypted: true });`
- **`js/ts:S6302` — Políticas AWS IAM não devem conceder todos os privilégios ('Action: "*"')** (`BLOCKER`): Especificar '*' na lista de 'actions' viola o princípio do menor privilégio, concedendo permissões administrativas totais caso a credencial vaze. | ❌ `new iam.PolicyStatement({ actions: ['*'], resources: [bucket.bucketArn] });` → ✅ `new iam.PolicyStatement({ actions: ['s3:GetObject', 's3:PutObject'], resources: [bucket.bucketArn] });`
- **`js:S6304` — Políticas AWS IAM não devem conceder acesso a todos os recursos ('Resource: "*"')** (`BLOCKER`): Usar '*' em 'resources' permite que as ações autorizadas sejam executadas sobre qualquer recurso da conta AWS. - **`js/ts:S6333` — Criar endpoints públicos AWS API Gateway sem autorização é sensível à segurança** (`BLOCKER`): Definir 'authorizationType: apigateway.AuthorizationType.NONE' em rotas de API expõe recursos internos sem qualquer controle de acesso. | ❌ `api.root.addMethod('POST', integration, { authorizationType: apigateway.AuthorizationType.NONE });` → ✅ `api.root.addMethod('POST', integration, { authorizationType: apigateway.AuthorizationType.IAM });`

## 🟠 CRITICAL (Falha em `Critical Issues > 0`) (61 regras)

- **`js:S1067` — Expressões não devem ser excessivamente complexas** (`CRITICAL`): A complexidade de uma expressão condicional não deve ultrapassar o limite máximo de 3 operadores lógicos ('&&', '||', '?'). Extraia subexpressões para variáveis ou funções auxiliares. *(Params: `max=3`)* | ❌ `if (a && b && c && d && e) { doSomething(); }` → ✅ `const isReady = a && b && c; const isAuthorized = d && e; if (isReady && isAuthorized) { doSomething(); }`

Caso seja intencional (ex.: no-op), adicione um comentário explicativo. | ❌ `function onError(err: Error) {}` → ✅ `function onError(err: Error) { /* Ignorado intencionalmente no modo offline */ }`

- **`js:S121` — Estruturas de controle devem sempre usar chaves** (`CRITICAL`): Omitir chaves em blocos 'if', 'else', 'for' ou 'while' aumenta o risco de bugs ao adicionar novas linhas posteriormente. | ❌ `if (isAdmin) grantAccess();` → ✅ `if (isAdmin) { grantAccess(); }`

- **`js:S134` — Estruturas de fluxo de controle não devem ter aninhamento excessivo** (`CRITICAL`): Aninhar 'if', 'for', 'while', 'switch' ou 'try' além do limite máximo de 3 níveis torna o código difícil de ler e testar. Use retornos antecipados ou funções auxiliares. *(Params: `maximumNestingLevel=3`)* | ❌ `if (a) { if (b) { for (const x of list) { if (x > 0) { doWork(x); } } } }` → ✅ `if (!a || !b) return; for (const x of list.filter(v => v > 0)) { doWork(x); }`

- **`js:S1539` — O modo estrito ('use strict') deve ser usado com cautela** (`CRITICAL`): Em módulos ES6 ou código TypeScript, o modo estrito já é ativado automaticamente; diretivas 'use strict' manuais ou globais podem ser desnecessárias ou afetar scripts concatenados. | ❌ `'use strict'; export function run() {}` → ✅ `export function run() {}`
- **`js:S1541` — A Complexidade Ciclomática de funções não deve ser muito alta** (`CRITICAL`): Funções cuja complexidade ciclomática excede o limite de 10 possuem muitos caminhos de decisão e são difíceis de testar. Divida a função em partes menores. *(Params: `maximumFunctionComplexityThreshold=10`)* | ❌ `function evaluate(a, b, c, d, e) { /* mais de 10 desvios if/else/case/&&/|| */ }` → ✅ `function evaluate(input: Input) { return validate(input) && calculate(input); }`
- **`js:S1821` — Instruções 'switch' não devem ser aninhadas** (`CRITICAL`): Aninhar um 'switch' dentro de outro torna o fluxo de controle extremamente confuso. ## 🔵 MINOR — Bugs e Vulnerabilidades (Rebaixa `Reliability/Security Rating` para `B`) (13 regras)

- **`js/ts:S1226` — Parâmetros de função e exceções capturadas não devem ser sobrescritos antes de serem lidos** (`MINOR/BUG`): Atribuir um novo valor a um parâmetro ou variável de 'catch' antes de ler seu valor original torna o valor recebido completamente inútil. | ❌ `` function greet(name: string) { name = 'Visitante'; return `Olá, ${name}`; } `` → ✅ `` function greet(name = 'Visitante') { return `Olá, ${name}`; } ``
- **`js:S1321` — Instruções 'with' não devem ser utilizadas** (`MINOR/BUG`): A instrução 'with' é proibida no modo estrito ('use strict'), degrada a performance e torna impossível prever a qual objeto uma variável pertence. | ❌ `with (mathObj) { result = sin(x) + cos(y); }` → ✅ `const result = mathObj.sin(x) + mathObj.cos(y);`
- **`js:S1530` — Declarações de função não devem ser feitas dentro de blocos** (`MINOR/BUG`): Declarar funções ('function foo() {}') dentro de blocos 'if' ou 'for' teve comportamento inconsistente entre motores JS. Use expressões de função ou arrow functions atribuídas a 'const'. | ❌ `if (isAdmin) { function action() { return 'admin'; } }` → ✅ `const action = isAdmin ? () => 'admin' : () => 'guest';`
- **`js:S2427` — A base numérica (radix) deve ser informada ao chamar 'parseInt'** (`MINOR/BUG`): Chamar 'parseInt' sem especificar o segundo argumento (radix) pode causar interpretações inesperadas da base numérica. Informe explicitamente a base (ex.: 10). | ❌ `const num = parseInt(inputStr);` → ✅ `const num = Number.parseInt(inputStr, 10);`
- **`js/ts:S3001` — O operador 'delete' não deve ser usado em variáveis** (`MINOR/BUG`): 'delete' serve apenas para remover propriedades de objetos; aplicá-lo a variáveis é proibido no modo estrito e não libera a variável. | ❌ `let x = 10; delete x;` → ✅ `const obj: { x?: number } = { x: 10 }; delete obj.x;`
- **`js/ts:S4158` — Coleções sabidamente vazias não devem ser acessadas ou iteradas** (`MINOR/BUG`): Iterar ou buscar elementos em um array, 'Set' ou 'Map' recém-criado e vazio nunca executará nada e indica código morto ou esquecimento de popular a coleção. | ❌ `const items: string[] = []; for (const item of items) { process(item); }` → ✅ `const items = loadItems(); for (const item of items) { process(item); }`
- **`js/ts:S5842` — Subpadrões repetidos em expressões regulares não devem casar com a string vazia** (`MINOR/BUG`): Quantificar com '*' ou '+' um grupo cujos ramos são todos opcionais (ex.: '(?:a?|b?)*') pode casar com a string vazia infinitas vezes e causar lentidão extrema. | ❌ `const regex = /(?:a*|b*)*/;` → ✅ `const regex = /[ab]*/;`
- **`js:S5867` — Clusters de grafemas Unicode não devem ser usados dentro de classes de caracteres em regex** (`MINOR/BUG`): Colocar emojis compostos ou caracteres com múltiplos code points dentro de colchetes '[...]' faz a regex casar com cada unidade isoladamente em vez do símbolo completo. Use alternância '(?:...)'. | ❌ `const regex = /[🇯🇵🇰🇷]/u;` → ✅ `const regex = /(?:🇯🇵|🇰🇷)/u;`
- **`js/ts:S6321` — O acesso a serviços de administração (SSH/RDP) deve ser restrito a IPs específicos** (`MINOR/VULNERABILITY`): Liberar as portas 22 (SSH) ou 3389 (RDP) para '0.0.0.0/0' ('Peer.anyIpv4()') em Security Groups expõe servidores a ataques constantes de força bruta. | ❌ `securityGroup.addIngressRule(ec2.Peer.anyIpv4(), ec2.Port.tcp(22));` → ✅ `securityGroup.addIngressRule(ec2.Peer.ipv4('10.0.0.0/16'), ec2.Port.tcp(22));`
- **`Web:FlashUsesBothObjectAndEmbedCheck` — Conteúdo multimídia embarcado deve ser compatível ou usar tags modernas HTML5** (`MINOR/BUG`): Caso use <object> legado, garanta fallback adequado ou prefira <video>/<audio> nativos do HTML5. | ❌ `<object data="movie.swf"></object>` → ✅ `<video src="movie.mp4" controls></video>`
- **`Web:FrameWithoutTitleCheck` — Elementos <iframe> e <frame> devem possuir o atributo title** (`MINOR/BUG`): Todo <iframe> deve ter um atributo title descritivo para acessibilidade em leitores de tela. | ❌ `<iframe src="https://exemplo.com/mapa"></iframe>` → ✅ `<iframe src="https://exemplo.com/mapa" title="Mapa de agências"></iframe>`
- **`Web:ItemTagNotWithinContainerTagCheck` — Tags de item (<li>, <dt>, <dd>) devem estar dentro de um contêiner válido (<ul>, <ol>, <dl>)** (`MINOR/BUG`): Elementos <li> só podem ser filhos diretos de <ul>, <ol> ou <menu>; <dt> e <dd> devem estar dentro de <dl>. | ❌ `<div><li>Item solto</li></div>` → ✅ `<ul><li>Item da lista</li></ul>`
- **`Web:MouseEventWithoutKeyboardEquivalentCheck` — Eventos de mouse devem ter equivalentes de teclado para acessibilidade** (`MINOR/BUG`): Ao usar onClick/onMouseOver/onMouseOut em elementos interativos, garanta suporte a teclado (onFocus/onBlur/onKeyDown) ou use <button> nativo. | ❌ `<div onmouseover="showTip()" onmouseout="hideTip()">Ajuda</div>` → ✅ `<button type="button" onmouseover="showTip()" onfocus="showTip()" onmouseout="hideTip()" onblur="hideTip()">Ajuda</button>`
