## 🔴 BLOCKER (Falha em `Blocker Issues > 0`) (22 regras)

- **`javascript:S1219` — Instruções 'switch' não devem conter rótulos diferentes de 'case'** (`BLOCKER`): Inserir rótulos de salto ('label:') dentro de blocos 'switch' é altamente confuso e frequentemente decorre de um erro de digitação em 'case' ou 'default'. | ❌ `switch (day) { case 1:defaul: return 'Segunda'; }` → ✅ `switch (day) { case 1: default: return 'Segunda'; }`
- **`javascript:S128` — Cláusulas 'case' de um 'switch' devem terminar com uma instrução 'break' incondicional** (`BLOCKER`): Deixar a execução vazar de um 'case' para o próximo (fallthrough) sem 'break', 'return' ou 'throw' quase sempre introduz bugs silenciosos. | ❌ `switch (x) { case 1: doOne(); case 2: doTwo(); break; }` → ✅ `switch (x) { case 1: doOne(); break; case 2: doTwo(); break; }`
- **`javascript:S1314` — Literais octais legados não devem ser utilizados** (`BLOCKER`): Números iniciados com zero (como '071') são interpretados como octais em modo não-estrito, o que confunde desenvolvedores. Use o prefixo '0o' ou decimal. | ❌ `const fileMode = 0755;` → ✅ `const fileMode = 0o755;`
- **`javascript:S1526` — Variáveis declaradas com 'let' ou 'const' não devem ser acessadas antes da declaração** (`BLOCKER`): Acessar variáveis 'let' ou 'const' na Temporal Dead Zone (antes da linha de declaração) lança um 'ReferenceError' em tempo de execução. | ❌ `console.log(count); let count = 0;` → ✅ `let count = 0; console.log(count);`
- **`javascript:S1527` — Palavras reservadas futuras não devem ser usadas como identificadores** (`BLOCKER`): Usar palavras reservadas da especificação ECMAScript (como 'implements', 'interface', 'package', 'private') como nomes de variáveis causa erros no modo estrito. | ❌ `const package = 'meu-pacote';` → ✅ `const packageName = 'meu-pacote';`
- **`javascript:S2068` — Credenciais fixadas no código (hardcoded) são sensíveis à segurança** (`BLOCKER`): Senhas e segredos atribuídos a variáveis contendo termos como 'password', 'pwd' ou 'passwd' no código-fonte podem ser comprometidos. Use cofres de segredos ou variáveis de ambiente. *(Params: `passwordWords=password, pwd, passwd`)* | ❌ `const password = 'SuperSecretPassword123!';` → ✅ `const password = process.env.DB_PASSWORD;`
- **`javascript:S2189` — Laços de repetição não devem ser infinitos** (`BLOCKER`): Um laço cuja condição nunca se torna falsa e que não possui 'break', 'return' ou 'throw' travará a execução do programa. | ❌ `while (true) { doWork(); }` → ✅ `while (hasMoreWork()) { doWork(); }`
- **`javascript:S2699` — Testes automatizados devem conter asserções** (`BLOCKER`): Um caso de teste que apenas executa funções sem verificar nenhum resultado com 'expect' ou 'assert' só detecta exceções não tratadas e dá falsa segurança. | ❌ `test('calcula soma', () => { sum(2, 3); });` → ✅ `test('calcula soma', () => { expect(sum(2, 3)).toBe(5); });`
- **`javascript:S2703` — Variáveis devem sempre ser declaradas explicitamente com 'let' ou 'const'** (`BLOCKER`): Atribuir valor a um identificador não declarado cria uma variável global implícita (ou lança erro em modo estrito), poluindo o escopo global. | ❌ `function countItems() { total = 10; return total; }` → ✅ `function countItems() { const total = 10; return total; }`
- **`javascript:S2755` — Analisadores XML (parsers) não devem ser vulneráveis a ataques XXE** (`BLOCKER`): Habilitar a resolução de entidades externas (XXE) ao processar XML não confiável permite leitura de arquivos locais e ataques de SSRF. | ❌ `libxmljs.parseXml(xmlInput, { noent: true });` → ✅ `libxmljs.parseXml(xmlInput, { noent: false });`
- **`javascript:S2970` — Asserções em testes Jest devem ser completas** (`BLOCKER`): Referenciar métodos de asserção do Jest (como expect(x).toBeNull ou expect(x).toBeDefined sem parênteses) sem invocá-los faz o teste passar silenciosamente sem validar nada. | ❌ `expect(result).toBeDefined;` → ✅ `expect(result).toBeDefined();`
- **`javascript:S3516` — Funções não devem retornar sempre o mesmo valor constante** (`BLOCKER`): Se uma função possui múltiplos pontos de retorno mas todos retornam exatamente o mesmo valor, o retorno é invariante e pode indicar um erro de lógica. | ❌ `function validate(x: number) { if (x < 0) { logError(); return false; } return false; }` → ✅ `function validate(x: number) { if (x < 0) { logError(); return false; } return true; }`
- **`javascript:S3796` — Callbacks de métodos de array devem conter instruções 'return'** (`BLOCKER`): Métodos como 'map', 'filter', 'find', 'every', 'some' e 'reduce' dependem do valor retornado pelo callback; esquecer o 'return' preenche o resultado com 'undefined'. | ❌ `const ids = users.map(u => { u.id; });` → ✅ `const ids = users.map(u => u.id);`
- **`javascript:S3827` — Variáveis devem ser declaradas antes de serem utilizadas** (`BLOCKER`): Referenciar um identificador que não foi declarado em nenhum escopo acessível nem importado lança um 'ReferenceError' em tempo de execução. | ❌ `function show() { return undeclaredVar + 1; }` → ✅ `function show(declaredVar: number) { return declaredVar + 1; }`
- **`javascript:S6265` — Conceder acesso público a objetos AWS S3 via ACLs é sensível à segurança** (`BLOCKER`): Usar ACLs como 'PUBLIC_READ' ou 'PUBLIC_READ_WRITE' em buckets S3 expõe dados sensíveis publicamente. Utilize 'PRIVATE' e políticas de acesso restritas. | ❌ `new s3.Bucket(this, 'MyBucket', { accessControl: s3.BucketAccessControl.PUBLIC_READ });` → ✅ `new s3.Bucket(this, 'MyBucket', { accessControl: s3.BucketAccessControl.PRIVATE });`
- **`javascript:S6268` — Permitir requisições HTTP não criptografadas em buckets AWS S3 é sensível à segurança** (`BLOCKER`): Buckets S3 devem exigir conexões TLS ('enforceSSL: true') para evitar que dados e tokens de acesso sejam interceptados em trânsito. | ❌ `new s3.Bucket(this, 'MyBucket', { enforceSSL: false });` → ✅ `new s3.Bucket(this, 'MyBucket', { enforceSSL: true });`
- **`javascript:S6270` — Políticas AWS IAM que concedem acesso a qualquer principal ('*') são sensíveis à segurança** (`BLOCKER`): Usar 'new iam.AnyPrincipal()' ou 'Principal: "*"' em uma política de recurso com efeito 'ALLOW' concede acesso público irrestrito a qualquer conta AWS. | ❌ `new iam.PolicyStatement({ effect: iam.Effect.ALLOW, principals: [new iam.AnyPrincipal()], actions: ['s3:GetObject'] });` → ✅ `new iam.PolicyStatement({ effect: iam.Effect.ALLOW, principals: [new iam.AccountRootPrincipal()], actions: ['s3:GetObject'] });`
- **`javascript:S6299` — Desabilitar a criptografia em sistemas de arquivos AWS EFS é sensível à segurança** (`BLOCKER`): Sistemas de arquivos EFS devem ter a criptografia em repouso habilitada ('encrypted: true') para proteger dados compartilhados. | ❌ `new efs.FileSystem(this, 'Fs', { vpc, encrypted: false });` → ✅ `new efs.FileSystem(this, 'Fs', { vpc, encrypted: true });`
- **`javascript:S6302` — Políticas AWS IAM não devem conceder todos os privilégios ('Action: "*"')** (`BLOCKER`): Especificar '*' na lista de 'actions' viola o princípio do menor privilégio, concedendo permissões administrativas totais caso a credencial vaze. | ❌ `new iam.PolicyStatement({ actions: ['*'], resources: [bucket.bucketArn] });` → ✅ `new iam.PolicyStatement({ actions: ['s3:GetObject', 's3:PutObject'], resources: [bucket.bucketArn] });`
- **`javascript:S6304` — Políticas AWS IAM não devem conceder acesso a todos os recursos ('Resource: "*"')** (`BLOCKER`): Usar '*' em 'resources' permite que as ações autorizadas sejam executadas sobre qualquer recurso da conta AWS. Restrinja aos ARNs específicos necessários. | ❌ `new iam.PolicyStatement({ actions: ['s3:DeleteObject'], resources: ['*'] });` → ✅ `` new iam.PolicyStatement({ actions: ['s3:DeleteObject'], resources: [`${bucket.bucketArn}/*`] }); ``
- **`javascript:S6329` — Instâncias AWS EC2 e bancos RDS não devem receber endereços IP públicos** (`BLOCKER`): Atribuir IPs públicos ('publiclyAccessible: true' ou sub-redes públicas) a bancos de dados e servidores internos expõe a infraestrutura diretamente à internet. | ❌ `new rds.DatabaseInstance(this, 'Db', { engine, vpc, publiclyAccessible: true });` → ✅ `new rds.DatabaseInstance(this, 'Db', { engine, vpc, publiclyAccessible: false });`
- **`javascript:S6333` — Criar endpoints públicos AWS API Gateway sem autorização é sensível à segurança** (`BLOCKER`): Definir 'authorizationType: apigateway.AuthorizationType.NONE' em rotas de API expõe recursos internos sem qualquer controle de acesso. | ❌ `api.root.addMethod('POST', integration, { authorizationType: apigateway.AuthorizationType.NONE });` → ✅ `api.root.addMethod('POST', integration, { authorizationType: apigateway.AuthorizationType.IAM });`
