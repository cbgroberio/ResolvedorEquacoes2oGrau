## 🛡️ Métricas Obrigatórias do Quality Gate

## 🟠 CRITICAL (Falha em `Critical Issues > 0`) (2 regras)

- **`Web:S5258` — Tabelas de dados devem possuir uma descrição (<caption> ou aria-label/aria-describedby)** (`CRITICAL`): Adicione <caption> ou aria-label/aria-labelledby na tag <table> para descrever o propósito da tabela aos leitores de tela. | ❌ `<table><tr><th scope="col">Conta</th></tr></table>` → ✅ `<table aria-label="Extrato de contas"><caption>Extrato Mensal</caption><tr><th scope="col">Conta</th></tr></table>`
- **`Web:S5260` — Células de dados em tabelas complexas devem estar associadas aos cabeçalhos (headers/id)** (`CRITICAL`): Em tabelas com múltiplos níveis de cabeçalho, associe <td> aos respectivos <th id="..."> via atributo headers ou scope. | ❌ `<table><tr><th>Grupo</th></tr><tr><td>Dado</td></tr></table>` → ✅ `<table><tr><th id="col-grupo" scope="col">Grupo</th></tr><tr><td headers="col-grupo">Dado</td></tr></table>`

## 🟡 MAJOR (Falha em `Major Issues > 0`) (37 regras)

- **`Web:AvoidCommentedOutCodeCheck` — Trechos de código HTML comentados devem ser removidos** (`MAJOR`): Não deixe tags e blocos HTML desativados dentro de comentários <!-- ... -->; remova-os e use o histórico do Git. | ❌ `<!-- <div class="old"><p>Antigo</p></div> --> <div class="new">Atual</div>` → ✅ `<div class="new">Atual</div>`
- **`Web:DoctypePresenceCheck` — Declaração <!DOCTYPE> deve estar presente em páginas HTML** (`MAJOR`): Todo documento HTML completo deve iniciar com <!DOCTYPE html> para evitar que o navegador entre em Quirks Mode. | ❌ `<html><head><title>App</title></head><body></body></html>` → ✅ `<!DOCTYPE html> <html lang="pt-BR"><head><title>App</title></head><body></body></html>`
- **`Web:MetaRefreshCheck` — Tags <meta http-equiv="refresh"> não devem ser utilizadas** (`MAJOR`): Redirecionamentos ou recarregamentos automáticos via meta refresh prejudicam a acessibilidade e o controle do usuário; use redirecionamento HTTP 3xx ou roteamento JS. | ❌ `<meta http-equiv="refresh" content="5;url=/home">` → ✅ `<!-- Redirecionar via HTTP 302/301 no backend ou router -->`
- **`Web:PageWithoutTitleCheck` — Todo elemento <head> deve conter uma tag <title>** (`MAJOR`): Documentos HTML com <head> precisam de um <title> não vazio para identificação da aba e acessibilidade. | ❌ `<head><meta charset="utf-8"></head>` → ✅ `<head><meta charset="utf-8"><title>Portal Corporativo</title></head>`
- **`Web:S1134` — Comentários FIXME devem ser resolvidos antes do envio** (`MAJOR`): Marcações FIXME indicam bugs ou pendências críticas que precisam ser corrigidas antes de integrar o código. | ❌ `<!-- FIXME: corrigir alinhamento no mobile -->` → ✅ `<!-- Alinhamento responsivo ajustado com flexbox -->`
- **`Web:S1827` — Atributos HTML obsoletos (deprecated) no HTML5 não devem ser utilizados** (`MAJOR`): Substitua atributos visuais obsoletos (align, bgcolor, border, cellpadding, cellspacing, width em td/th) por CSS. | ❌ `<table border="1" cellpadding="4" bgcolor="#fff">` → ✅ `<table class="tabela-dados">`
- **`Web:S4084` — Elementos <video> e <audio> devem possuir trilhas (<track>) de acessibilidade** (`MAJOR`): Elementos de mídia devem incluir <track kind="captions"> ou <track kind="subtitles"> para usuários com deficiência auditiva. | ❌ `<video src="treinamento.mp4" controls></video>` → ✅ `<video src="treinamento.mp4" controls><track kind="captions" src="legenda.vtt" srclang="pt" label="Português"></video>`
- **`Web:S4645` — Tags de fechamento HTML não devem ser redundantes ou órfãs** (`MAJOR`): Toda tag de fechamento deve corresponder a uma tag aberta válida; elementos void (<br>, <img>, <input>) não têm tag de fechamento. | ❌ `<input type="text"></input></div>` → ✅ `<div><input type="text"></div>`
- **`Web:S5247` — Desabilitar o auto-escape em templates HTML é sensível à segurança (XSS)** (`MAJOR`): Evite renderizar HTML bruto não sanitizado (ex: innerHTML, th:utext, v-html) para prevenir ataques de Cross-Site Scripting (XSS). | ❌ `<div [innerHTML]="comentarioUsuario"></div>` → ✅ `<div>{{ comentarioUsuario }}</div>`
- **`Web:S5254` — A tag <html> deve possuir o atributo lang** (`MAJOR`): Defina o idioma principal do documento na tag <html> (ex: lang="pt-BR") para síntese de voz correta em leitores de tela. | ❌ `<!DOCTYPE html><html><head><title>App</title></head></html>` → ✅ `<!DOCTYPE html><html lang="pt-BR"><head><title>App</title></head></html>`
- **`Web:S5255` — O atributo tabindex não deve ter valores positivos maiores que 0** (`MAJOR`): Usar tabindex="1", "2", etc. quebra a ordem natural de navegação por teclado da página; use apenas tabindex="0" ou "-1". | ❌ `<button tabindex="3">Salvar</button>` → ✅ `<button tabindex="0">Salvar</button>`
- **`Web:S5256` — Tabelas HTML (<table>) devem possuir cabeçalhos (<th>)** (`MAJOR`): Toda tabela de dados deve conter células de cabeçalho <th> para que leitores de tela associem colunas e linhas aos dados. | ❌ `<table><tr><td>Nome</td><td>Valor</td></tr></table>` → ✅ `<table><thead><tr><th scope="col">Nome</th><th scope="col">Valor</th></tr></thead></table>`
- **`Web:S5257` — Tabelas de layout não devem usar elementos semânticos de tabelas de dados** (`MAJOR`): Não use <table> para layout visual; caso inevitável com role="presentation", não inclua <th>, <caption> ou summary. | ❌ `<table role="presentation"><tr><th>Menu</th></tr></table>` → ✅ `<div class="layout-grid"><nav>Menu</nav></div>`
- **`Web:S6793` — Chaves de acesso (accesskey) não devem ser utilizadas em elementos HTML** (`MAJOR`): O atributo accesskey entra em conflito com atalhos do navegador e de tecnologias assistivas (leitores de tela). | ❌ `<button accesskey="s">Salvar</button>` → ✅ `<button type="submit">Salvar</button>`
- **`Web:S6807` — Roles ARIA válidos e não abstratos devem ser utilizados** (`MAJOR`): O atributo role deve conter apenas valores WAI-ARIA válidos e concretos (não use roles abstratos como command, composite, input, landmark). | ❌ `<div role="command">Ação</div>` → ✅ `<button type="button">Ação</button>`
- **`Web:S6811` — Atributos aria-* devem possuir nomes válidos da especificação WAI-ARIA** (`MAJOR`): Verifique a grafia de todos os atributos aria-*; nomes inexistentes são ignorados pelos leitores de tela. | ❌ `<button aria-labeledby="titulo">Fechar</button>` → ✅ `<button aria-labelledby="titulo">Fechar</button>`
- **`Web:S6819` — Preferir elementos HTML semânticos nativos em vez de roles ARIA equivalentes** (`MAJOR`): Use tags HTML nativas (<button>, <nav>, <main>, <header>, <input>) em vez de <div role="...">. | ❌ `<div role="button" tabindex="0">Confirmar</div>` → ✅ `<button type="button">Confirmar</button>`
- **`Web:S6821` — Elementos com roles ARIA devem possuir todos os atributos aria-* obrigatórios para aquele role** (`MAJOR`): Roles como checkbox, combobox, slider e scrollbar exigem atributos de estado obrigatórios (ex: aria-checked, aria-expanded, aria-valuenow). | ❌ `<div role="checkbox" tabindex="0">Aceito</div>` → ✅ `<div role="checkbox" aria-checked="false" tabindex="0">Aceito</div>`
- **`Web:S6822` — Roles ARIA redundantes não devem ser adicionados a elementos semânticos nativos** (`MAJOR`): Não repita o role implícito de um elemento HTML (ex: <button role="button">; exceção permitida no perfil: <nav role="navigation">). *(Params: `allowedRedundantRoles=nav=navigation`)* | ❌ `<button role="button">Enviar</button>` → ✅ `<button type="button">Enviar</button>`
- **`Web:S6823` — Elementos que não suportam estados ou propriedades ARIA específicos não devem recebê-los** (`MAJOR`): Use apenas atributos aria-* compatíveis com o elemento HTML ou com o role definido nele. | ❌ `<a href="/home" aria-checked="true">Início</a>` → ✅ `<a href="/home" aria-current="page">Início</a>`
- **`Web:S6824` — Valores de propriedades e estados ARIA devem respeitar o tipo esperado** (`MAJOR`): Atributos aria-* devem receber valores válidos para seu tipo (true/false para booleanos, IDs válidos, números, tokens permitidos). | ❌ `<button aria-expanded="sim">Menu</button>` → ✅ `<button aria-expanded="true">Menu</button>`
- **`Web:S6825` — Elementos ocultos com aria-hidden="true" não devem ser focáveis** (`MAJOR`): Não aplique aria-hidden="true" em elementos focáveis (botões, links, inputs ativos), pois o usuário navegará com Tab até um item invisível ao leitor de tela. | ❌ `<button aria-hidden="true">Fechar</button>` → ✅ `<button type="button" aria-label="Fechar"><span aria-hidden="true">&times;</span></button>`
- **`Web:S6840` — Valores do atributo autocomplete em campos de formulário devem ser válidos** (`MAJOR`): Use tokens válidos da especificação HTML para o atributo autocomplete (ex: name, email, username, current-password, off). | ❌ `<input type="text" autocomplete="nome-completo">` → ✅ `<input type="text" autocomplete="name">`
- **`Web:S6841` — Elementos de cabeçalho (<h1> a <h6>) devem ter conteúdo textual acessível** (`MAJOR`): Tags de título <h1>-<h6> não podem estar vazias nem conter apenas imagens sem alt ou ícones ocultos. | ❌ `<h2><i class="fa-user" aria-hidden="true"></i></h2>` → ✅ `<h2><i class="fa-user" aria-hidden="true"></i> Perfil do Usuário</h2>`
- **`Web:S6842` — Elementos semânticos não interativos não devem receber handlers de eventos interativos** (`MAJOR`): Não adicione onclick/onkeydown diretamente em elementos não interativos como <p>, <li>, <div> sem convertê-los em botões/links acessíveis. | ❌ `<li onclick="selecionarItem()">Opção 1</li>` → ✅ `<li><button type="button" onclick="selecionarItem()">Opção 1</button></li>`
- **`Web:S6843` — Elementos não interativos não devem receber roles ARIA interativos** (`MAJOR`): Evite transformar elementos de estrutura (como <h1>, <p>, <ul>, <table>) em controles interativos via role="button" ou role="link". | ❌ `<h2 role="button" onclick="abrir()">Seção</h2>` → ✅ `<h2><button type="button" onclick="abrir()">Seção</button></h2>`
- **`Web:S6844` — Controles de formulário devem estar associados a um rótulo (<label>)** (`MAJOR`): Todo <input>, <select> e <textarea> deve ter um <label for="id"> associado ou atributo aria-label/aria-labelledby. | ❌ `<input type="text" id="cpf" name="cpf">` → ✅ `<label for="cpf">CPF</label><input type="text" id="cpf" name="cpf">`
- **`Web:S6845` — Tags <label> devem possuir texto descritivo e estar associadas a um controle** (`MAJOR`): Um elemento <label> não deve estar vazio e precisa envolver um input ou apontar para seu id via atributo for. | ❌ `<label></label><input id="nome" type="text">` → ✅ `<label for="nome">Nome Completo</label><input id="nome" type="text">`
- **`Web:S6846` — Elementos <blink> e <marquee> não devem ser utilizados** (`MAJOR`): Tags de animação obsoletas como <marquee> e <blink> causam problemas graves de acessibilidade e não fazem parte do HTML5. | ❌ `<marquee>Aviso importante</marquee>` → ✅ `<div role="alert" class="aviso">Aviso importante</div>`
- **`Web:S6847` — Eventos de clique em elementos não nativos exigem suporte a teclado (onKeyDown/onKeyUp)** (`MAJOR`): Elementos que recebem onclick (quando não são <button>, <a> ou <input>) também precisam tratar eventos de teclado (Enter/Space). | ❌ `<span role="button" tabindex="0" onclick="acao()">Ação</span>` → ✅ `<button type="button" onclick="acao()">Ação</button>`
- **`Web:S6848` — Elementos não interativos não devem receber tabindex para navegação sequencial** (`MAJOR`): Não adicione tabindex>="0" em elementos estáticos (<div>, <p>, <span> sem role interativo), pois usuários de teclado ficarão presos em itens sem ação. | ❌ `<p tabindex="0">Texto informativo</p>` → ✅ `<p>Texto informativo</p>`
- **`Web:S6850` — O texto alternativo (alt) de imagens não deve conter palavras redundantes como 'imagem', 'foto' ou 'ícone'** (`MAJOR`): Leitores de tela já anunciam que o elemento é uma imagem; descreva apenas o conteúdo ou função da imagem no atributo alt. | ❌ `<img src="grafico.png" alt="Imagem do gráfico de vendas">` → ✅ `<img src="grafico.png" alt="Gráfico de vendas do 1º trimestre">`
- **`Web:S6851` — Elementos com role="img" devem possuir texto alternativo via aria-label ou aria-labelledby** (`MAJOR`): Qualquer elemento marcado com role="img" (como SVGs ou ícones) precisa de um nome acessível. | ❌ `<div role="img" class="icone-sucesso"></div>` → ✅ `<div role="img" aria-label="Operação concluída com sucesso" class="icone-sucesso"></div>`
- **`Web:S6852` — Links (<a>) devem ter conteúdo textual acessível e um destino válido** (`MAJOR`): Tags <a> precisam conter texto legível (ou aria-label se contiverem apenas ícone) e um atributo href válido (não use href="#" ou "javascript:void(0)" para botões). | ❌ `<a href="#" onclick="abrirModal()"><i class="fa-plus"></i></a>` → ✅ `<button type="button" aria-label="Adicionar item" onclick="abrirModal()"><i class="fa-plus" aria-hidden="true"></i></button>`
- **`Web:S6853` — Elementos interativos não devem receber roles ARIA não interativos** (`MAJOR`): Não sobrescreva elementos interativos nativos (<button>, <a>, <input>) com roles estáticos como presentation, none ou article. | ❌ `<button role="presentation">Clique</button>` → ✅ `<button type="button">Clique</button>`
- **`Web:TableHeaderHasIdOrScopeCheck` — Células de cabeçalho <th> devem possuir o atributo scope ou id** (`MAJOR`): Todo <th> deve especificar scope="col" ou scope="row" (ou um id único referenciado por headers) para acessibilidade. | ❌ `<table><tr><th>Produto</th><th>Preço</th></tr></table>` → ✅ `<table><tr><th scope="col">Produto</th><th scope="col">Preço</th></tr></table>`
- **`Web:UnsupportedTagsInHtml5Check` — Tags HTML obsoletas e removidas no HTML5 não devem ser utilizadas** (`MAJOR`): Não utilize tags depreciadas como <center>, <font>, <big>, <strike>, <tt>, <acronym>, <frame>, <frameset>; utilize HTML5 semântico e CSS. | ❌ `<center><font color="red">Erro</font></center>` → ✅ `<p class="texto-centralizado texto-erro">Erro</p>`

## 🔵 MINOR — Bugs e Vulnerabilidades (Rebaixa `Reliability/Security Rating` para `B`) (4 regras)

- **`Web:FlashUsesBothObjectAndEmbedCheck` — Conteúdo multimídia embarcado deve ser compatível ou usar tags modernas HTML5** (`MINOR/BUG`): Caso use <object> legado, garanta fallback adequado ou prefira <video>/<audio> nativos do HTML5. | ❌ `<object data="movie.swf"></object>` → ✅ `<video src="movie.mp4" controls></video>`
- **`Web:FrameWithoutTitleCheck` — Elementos <iframe> e <frame> devem possuir o atributo title** (`MINOR/BUG`): Todo <iframe> deve ter um atributo title descritivo para acessibilidade em leitores de tela. | ❌ `<iframe src="https://exemplo.com/mapa"></iframe>` → ✅ `<iframe src="https://exemplo.com/mapa" title="Mapa de agências"></iframe>`
- **`Web:ItemTagNotWithinContainerTagCheck` — Tags de item (<li>, <dt>, <dd>) devem estar dentro de um contêiner válido (<ul>, <ol>, <dl>)** (`MINOR/BUG`): Elementos <li> só podem ser filhos diretos de <ul>, <ol> ou <menu>; <dt> e <dd> devem estar dentro de <dl>. | ❌ `<div><li>Item solto</li></div>` → ✅ `<ul><li>Item da lista</li></ul>`
- **`Web:MouseEventWithoutKeyboardEquivalentCheck` — Eventos de mouse devem ter equivalentes de teclado para acessibilidade** (`MINOR/BUG`): Ao usar onClick/onMouseOver/onMouseOut em elementos interativos, garanta suporte a teclado (onFocus/onBlur/onKeyDown) ou use <button> nativo. | ❌ `<div onmouseover="showTip()" onmouseout="hideTip()">Ajuda</div>` → ✅ `<button type="button" onmouseover="showTip()" onfocus="showTip()" onmouseout="hideTip()" onblur="hideTip()">Ajuda</button>`
